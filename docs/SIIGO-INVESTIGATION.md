# Investigation Report: IMSI → Siigo Export

Date: 2026-11-28
Scope: understand what IMSI must export, what Siigo Pyme 10.1 accepts, and what can be implemented without a license.

## 1. Summary

The investigation changed conclusions several times. The first subagent worked from the old handoff and the local `imsi-verify` clone, and concluded that IMSI exported quotations. Upon reviewing the most recent remote repository (`feat/first-release`, SHA `410ef36`), the correct conclusion is different:

- The queue implemented in 5c exports **Work Orders (WOs)**.
- **5c is implemented**: model, API, permissions, events, and synchronization command.
- **5d is not implemented**: there is no file generator or `SiigoExporter`.
- The Siigo layout remains **undefined** in the repository.

On the Siigo side:

- The documented route for commercial documents is an **extra-accounting movement** in an **.xlsx generated by Siigo**, not a custom CSV.
- The documented types are `Z` order, `Y` purchase order, and `V` quotation.
- **There is no “W.O.” type**.
- The IMSI W.O. has no prices; the company's actual W.O. does. This affects the file design.

Siigo Pyme 10.1 could not be run because the installation has no license. Therefore, this report is based on official documentation, local files, and the remote repository; it is not based on an actual upload.

## 4. What Siigo Pyme 10.1 Accepts

Official source:
`https://siigopyme2.portaldeclientes.siigo.com/interfaces-movimiento-extracontable/`

### 4.1 Format

- `Interfaces → Importaciones desde Excel → Movimiento extracontable`.
- A model `.xlsx` is generated from the installation.
- Headers go in row 5.
- The font, header rows, column order, and column names must not be changed.
- The model depends on the configured company/modules.

### 4.2 Columns and Types

Mandatory:

- TIPO DE DOCUMENTO
- CÓDIGO DOCUMENTO
- NÚMERO DE DOCUMENTO

Documented types:

- `Z` order
- `Y` purchase order
- `V` quotation

There is no “W.O.” type.

Optional columns:

- Third party
- Product
- Quantity
- Values
- Taxes
- Currency
- Comments
- Free fields

### 4.3 Limits of What Was Verified

An actual upload could not be performed. Therefore, it cannot be claimed that Siigo accepts a W.O. without values or rejects a specific row. What is documented is the `.xlsx` format, the `Z/Y/V` types, and the mandatory fields.

| “Siigo Pyme 10.1 has no useful format without a license” | Partially correct | Without a license, an upload cannot be validated; the documented format does exist. |

## 6. Why It Was So Confusing

1. **Free plans.** Free Siigo Contador is cloud accounting for one company. Free invoicing is a trial with limits. There is no evidence that either includes Pyme extra-accounting import.
2. **Format.** The repository refers to a “flat file CSV/TXT”; Siigo documents an `.xlsx` generated by the installation.
3. **Document.** IMSI exports W.O.s without prices; the Siigo extra-accounting movement has value columns. The company's actual W.O. does include prices, VAT (IVA), and withholding.
4. **No license.** The import menu could not be opened, and the actual template could not be generated. Verification was documentary.
5. **Open layout.** The repository states that columns, separator, and sample/template are still missing. There is no closed definition of 5d.

## 7. Proposals

### Proposal A — Implement 5d as a Provisional Adapter

- Create `SiigoExtracontableAdapter` with a clear contract.
- Generate an `.xlsx` using openpyxl.
- Put the columns in a configuration sheet or template.
- Map W.O. → `V` or `Z`; decide whether to use `Z` order or `V` quotation.
- Include: W.O. number, quotation, customer/NIT, date, product, description, unit, quantity, agreed date.
- Do not include prices if they are absent from the W.O.; leave value columns empty or set them to zero, marked as pending.
- Test with a synthetic workbook and contract tests.
- Do not claim that it loads into Siigo until an actual test exists.

### Proposal B — Mock + Hexagonal Port

- `AccountingExportPort` with `export_batch` and `validate` methods.
- `MockAccountingAdapter` for the demo.
- `SiigoExtracontableAdapter` as a placeholder.
- Tests for mapping, columns, errors, and idempotency.
- Document that the real integration is blocked by the license/template.

### Proposal C — Switch to Another External System

Only if a scope change is accepted:

- **Odoo Community + `l10n_co`**: 56k stars, official Colombian localization, API; heavier.
- **ERPNext + CO localization**: 41k stars, API, GPL-3.0; third-party Colombian localization.
- **Nubicta**: 19 stars, MIT, Colombia-focused; young; review its API/tests before using it.
- **Alegra**: 15-day trial, API, then paid.
- **Mock**: demo only, not a real integration.

A change of this kind requires an ADR and stakeholder acceptance; it is not just a README edit.

### Proposal D — Obtain a Template and Run a Controlled Test

- Ask Siigo for an `.xlsx` template generated from Pyme 10.1.
- Perform a test upload using a demo company.
- Compare the result with the documentation.
- If there is no license, look online for an officially published template or a verifiable example; do not assume columns.

## 10. Conclusion

IMSI has the 5c queue, but it does not have 5d or a functional Siigo adapter. Siigo Pyme 10.1 uses an extra-accounting movement `.xlsx` with types `Z/Y/V`; there is no W.O. type, and the column layout remains open. Without a license, an actual upload cannot be validated. The most honest next step is to implement the port and provisional adapter, test it with a mock, and document the limitation; alternatively, change scope through an ADR if Odoo/Nubicta/Alegra is chosen.
