# IMSI → Siigo Export: Corrected Verification

Date: 2026-11-28
Audits: `RemoteExportAudit` + `Siigo10Audit`.

## Verdict

- In the remote `feat/first-release`, SHA **`410ef36`**, the queue exports **Work Orders (O.T.)**, not quotations.
- **5c is implemented; 5d is not.** The file and the move to “Registrada en Siigo” are still pending.
- Siigo Pyme 10.1 **has no “O.T.” document type**. Its documented import path is **Interfaces → Importaciones desde Excel → Movimiento extracontable**, using an **.xlsx generated by the installation itself**, with types `Z` (pedido), `Y` (orden de compra) or `V` (cotización).
- IMSI's column layout is still **undefined**; the repository declares it a blocking open item.
- A custom CSV **does not enter** through the documented path. The output would have to be the extracontable model `.xlsx`, with headers in row 5 and immutable columns.

## What IMSI exports

The O.T. (`OT-YYYYMMDD-NNNNN`) with the source quotation as a reference. Fields defined in the remote code:

| Field | Status |
|---|---|
| `number` (O.T.) | defined |
| `quotation_number` | defined as a reference |
| `created_at` | defined |
| `customer_name`, `customer_tax_id` | defined |
| `items`: `product_code`, `description`, `unit_of_measure`, `quantity` | defined |
| `agreed_delivery_date` | defined |
| prices, VAT, advance, totals | **do not exist in the IMSI O.T.** |

The company's real O.T. does include prices, VAT and withholding; that conflicts with the design decision “O.T. without prices”.

## What Siigo 10.1 requires

Official source: <https://siigopyme2.portaldeclientes.siigo.com/interfaces-movimiento-extracontable/>

- `.xlsx` model generated from the installation, according to company/modules.
- Row 5 contains the column names; do not change the source, header rows, order or names.
- Required: **TIPO DE DOCUMENTO**, **CÓDIGO DOCUMENTO**, **NÚMERO DE DOCUMENTO**.
- Optional groups: third party, product, quantity, values, taxes, etc.
- There is no O.T. type; map to `V` cotización or `Z` pedido.
- `ExcelSIIGO.exe` exposes `GETEXT`/`PUSHEXT`; it uses `.xlsx`, not a custom CSV.

## Contradictions

1. **Design vs code:** the old handoff/README sometimes says quotations; the remote `410ef36` says O.T.
2. **CSV/TXT vs .xlsx:** the repository asks for a “flat file CSV/TXT”; Siigo 10.1 uses .xlsx.
3. **No prices vs useful import:** the IMSI O.T. has no values; the extracontable model has value columns.
4. **Numbering:** `OT-YYYYMMDD-NNNNN` is text; the company uses four-digit numeric sequences.
5. **Document type:** Siigo has no “O.T.”; the team must choose `V` or `Z`.

## Alternatives without a license

1. **Request a demo/educational license from Siigo** and generate the real model from that installation. This is the only way to validate columns and a test load.
2. **Implement a `SiigoExtracontableFormatter`** that produces the `.xlsx` with the official model; keep the layout in a replaceable piece and test with a synthetic workbook. Without a license, the real load cannot be validated.
3. **Use the existing wrappers** `javalenciacai/siigo-pyme-mcp` (MIT) or `siigo-pyme-excel-skill` (GitHub “Other” license) only if Siigo Pyme + Excel are installed; they do not replace Siigo.
4. **Nubicta** (`bvr218/nubicta`, MIT): Colombian accounting ERP with DIAN support; an open-source alternative, not a Siigo clone, and it requires migration.
5. **Odoo + Colombian localization / Facturalam:** heavier, but legal and with DIAN invoicing.
6. **Mock Siigo:** deliver the adapter and a sample file marked provisional; document that the real load is pending template/license.

## Siigo free plans

- **Siigo Contador free:** cloud product, one company, accounting/taxes/financial statements. The official page does not document Pyme extracontable import. **It is not stated** that it supports the O.T. → Pyme 10.1 flow.
- **Electronic invoicing free/trial:** cloud product with document/customer limits. It is not stated that it includes Pyme Excel/extracontable import.
- **Siigo Pyme 10.1:** the only product with the documented **movimiento extracontable** path and `EXCELSIIGO.exe`; it requires a license.

Do not present the free plans as a substitute for Pyme 10.1. They are alternatives for cloud invoicing/accounting, not for validating the Pyme layout.

## Scope change

Replacing Siigo with a mock, CSV or Nubicta **is a scope change**, not a README edit. It requires:

- An ADR recording the decision, the reason (no license), the affected adapter and the acceptance criteria.
- Explicit acceptance from the professor/client.
- A clear statement that the Siigo adapter is implemented/tested against a contract, but the real load is not validated.

## About “MDP”

I found no official Siigo term called “MDP”. Searches return transport MDP or protocols, not Siigo. If it means the **data model** or the **document module**, the exact name must be specified; do not invent it.
